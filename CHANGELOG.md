# Ändringslogg / Changelog

## Ej släppt / Unreleased

### Svenska
- **Bevakningen berättar vad den gör + parkerade filer prövas på nytt** — loggen visar nu vid start vilka bevakade mappar som laddats (`SCAN_WATCH: bevakning startad …`), varnar om en bevakad mapp inte finns (i stället för att tyst hoppa över den var 30:e sekund), och en fil som parkerats för att appen saknade formatet då **prövas automatiskt igen** när appen lärt sig leverantören eller fått ett inbyggt format via uppdatering — parkeringen är inte längre en återvändsgränd där filen fastnar för alltid trots att appen nu kan läsa den. Lyckas omprövningen registreras fakturan som vanligt; annars parkeras den igen med samma orsak.
- **Uppdatera direkt från tray-menyn** — högerklick på Fakturabunten-ikonen i systemfältet har nu **🔄 Sök ny version …** (samma flöde som Hjälp-menyn): fönstret tas fram och uppdateringsdialogen öppnas, så du slipper öppna appen först bara för att uppdatera.
- **Veriferade leverantörsformat inbyggda — ingen inlärning i appen behövs för dem** — leverantörer som matchats manuellt mot riktiga exempelfakturor tillsammans med dig (här i chatten) har nu sitt format inbyggt i appen: **Martin G Anderson**, **Direktglas** (Saint-Gobain-papper), **Pilkington**, **Swede Glass United** (faktura 19072: 706,00) och **AAG Automotive** (faktura 1019: 6 344,00). Inbyggda format kräver nu dessutom att att betala står på samma rad som sin etikett — i Swede Glass'/AAG:s kolumnsummor (rubrikrad följd av värderad) är första beloppet efter etiketten annars netto/exkl. moms ur fel kolumn; sådan text parkeras för granskning i stället för att bokföras fel. Bevakade mappar registrerar deras fakturor direkt utan att du först måste lära appen leverantören med 🎓, och inlärningsfrågan vid mapp-tillägg visas inte längre för dem. Formatet känns igen via org.nr/bankgiro eller det tryckta namnet på själva fakturan (aldrig via registerpostens namn, som kan heta Direktglas fast det står Saint-Gobain på papperet) och kräver alltid fakturanummer + att betala ur själva formatet — kommer texten radvis/kolumnbruten eller något saknas parkeras filen för granskning precis som förut, aldrig auto-registrerad med gissade värden. Dina egna inlärda mallar har fortfarande företräde, och för alla andra leverantörer gäller samma regel som förut: inlärning krävs innan mappen blir automatisk.
- **Original flyttas bara EN gång — ingen Arkiv-flytt vid export längre** — ett registrerat original får sin plats i årsmappen (`/pilkington/<fakturaår>/`) när fakturan registreras, och där stannar det. Tidigare flyttades det en andra gång till `Arkiv/<exportår>/` när fakturan exporterades som betald; den flytten är borttagen i både manuell export och autoexport. Vilka fakturor som är betalda håller registret (JSON) reda på — mappstrukturen speglar bara året. Arkiv/ ryms inte längre i skanningen, och original som redan ligger där sedan tidigare fungerar precis som förut.
- **Årssortering i bevakade mappar** — registrerade fakturors original flyttas nu automatiskt till en årsmapp efter fakturadatum (`/pilkington/2023/…`) i stället för att ligga i en enda stor hög. Nya auto-registreringar sorteras direkt, den befintliga högen eftersorteras vid nästa skanning och registrets sökväg pekas om i båda fallen. Parkerade (ännu ej registrerade) filer lämnas orörda, och utan läsbart datum flyttas ingenting. Skanningen ser numera även filerna inne i årsmapparna (så en faktura du själv lagt i `2023/` behandlas), medan `Arkiv/`-trädet med betalda original aldrig skannas om. Exportens arkivering till `Arkiv/<exportår>/` fungerar likadant för årssorterade original.
- **Fakturanummer läses aldrig som fel kolumn (hittat via riktiga Martin G Anderson-fakturor)** — PDF-text kan extraheras antingen etikett+värde i par eller som rubrikrad följd av värderad. Generiska mönster och mallar fångade förut nästa kolumnrubrik som ”fakturanummer” (t.ex. ”Fakturadatum”) eller sväljde resten av raden. Nu läses numret strikt som en enda token, rubrikord känns aldrig igen som nummer och mallar hoppar förbi rena rubrikrader. Det som inte kan läsas säkert lämnas tomt och väljs/markeras av dig i inlärningen — appen gissar aldrig fram ett nummer ur fel kolumn. Verifierat mot layouten: samlingsfaktura 906178 (att betala 3 491,00 på sida 2) och faktura 905034 läses med Fakturanr./Att betala/Fakturadatum/Förfallodatum-etiketterna; samlingsfakturans delbelopp per order används inte som total.
- **Kreditnotor får rätt belopp + antal klistras inte ihop med summor (hittat via riktiga Saint-Gobain-fakturor)** — en kreditnotas total står som ”Er Tillgodo”, men tolkaren kände inte igen etiketten och föll tillbaka på första Summa-raden; hos Saint-Gobain (”Summa Glas 1 2.642,50”) klistrades dessutom **antalet 1 ihop med nettobeloppet** och gav −12 642,50 i stället för −3 303,00. Nu känns ”Tillgodo” igen som totaletikett och ett ensamt heltal framför ett belopp tolkas som antal, inte som en del av summan. Verifierat mot layouten: den tvåsidiga faktura 9750271120 (totalen på sida 2) och kreditnota 9750269328 läses fullständigt efter en inlärning — och samma mall täcker både fakturor och kreditnotor, eftersom kreditnotans total hämtas generiskt när ”Att Betala” saknas.
- **Två formatfixar i fakturatolkningen (hittade via en riktig Pilkington/NSG-faktura)** — belopp med **punkt som tusentalsavskiljare** (t.ex. `4.374,00`) tolkades förut som 4,37; nu avgör sista skiljetecknet vad som är decimaler, så både svenskt `3.499,30` och US-format `1,234.56` blir rätt. Dessutom läses nu **år-först-datum med punkt eller snedstreck** (`2026.10.15`, `2026/10/15`). Verifierat mot layouten: med en inlärd mall läses Pilkington-fakturan fullständigt (fakturanummer, totalbelopp 4 374,00, datum, förfallodatum ur ”T.o.m.”); utan inlärning parkeras den säkert för granskning, precis som förut — den registreras aldrig med gissade värden.
- **Betald-markerade fakturor försvinner ur exporten** — tidigare tog ”Exportera alla” med även fakturor du själv markerat som betalda (bara Arkiverad/Makulerad uteslöts), så en redan betald faktura kunde exporteras och betalas en gång till av misstag. Nu bygger exporten — och exportknappens antal — på samma urval som allt annat som räknar obetalt: Betald/Arkiverad/Makulerad är alltid uteslutna. Markerar som betald gör du precis som förut: markera raderna i Fakturor och klicka **Markera som betalda** (fungerar för flera på en gång, och går att ångra med Ctrl+Z).
- **Kreditkänning vid inskanning + arkivflytt av betalda original** — tolkningen känner nu igen kreditfakturor/-notor (ordet på dokumentet) och ger dem negativt belopp, så de **minskar** ATT BETALA i stället för att öka den. Och när en faktura från en bevakad mapp har exporterats (betald) flyttas dess original automatiskt till `<leverantörsmapp>/Arkiv/<exportår>/` — både vid manuell export och autoexport — medan registret (JSON) pekas om till nya platsen så originalet fortfarande hittas till betal-PDF:er och historik. Inkorgen hålls därmed ren och betalda original samlas årsvis. Filer utanför bevakade mappar rörs aldrig, och en flytt som misslyckas stoppar aldrig exporten.
- **Max 10 fakturor per exportfil + original med som standard** — varje faktura är fortfarande en egen rad i betal-PDF:en, men en exportfil innehåller nu högst 10 rader: fler delas automatiskt upp på flera filer (`…-del1av3.pdf`, `…-del2av3.pdf`, …) med samma betalningsdatum och med historik + arkivering per fil. Det gäller både manuell export (alla/markerade) och autoexporten per leverantör — 23 obetalda hos en leverantör blir tre filer om 10/10/3 med eget tidigaste-förfall som betalningsdatum per fil. Dessutom bifogas **originalfakturorna i betal-PDF:en nu som standard** (går fortfarande att stänga av i Inställningar → 📎 Inkludera originalfakturor).
- **Ingen auto-import förrän leverantören är inlärd** — varje leverantör har sin egen layout/design, så en bevakad mapp registrerar inte längre automatiskt på bara generell tolkning: filen parkeras i stället (orsak ”ingen mall”) tills du lärt appen leverantören med 🎓-knappen (nytt erbjudande direkt när mappen läggs till förklarar varför). Finns en mall som träffar på filen blir mappen automatisk igen. Filer som parkerats före inlärningen tolkas dessutom om med mallen när du granskar dem, och för **flersidiga fakturor** sparas nu upp till 30 000 tecken fakturatext per fil (mot 4 000 förut) så betalningsblocket på sista sidan inte kapas vid granskning/omläsning — själva extraktionen läste redan alla sidor.
- **Lär appen från bevakad mapp** — när du lägger till en bevakad mapp frågar appen nu om du vill lära den läsa leverantörens fakturor (och knappen **🎓 Lär appen från mappen…** finns alltid i bevakningsrutan): appen skannar en av PDF:erna i mappen och du markerar manuellt vad som är fakturanummer, belopp, datum, förfallodatum och OCR — appen visar direkt vad den hittar för varje fält. Matchningen sparas som mall i `data/invoice_templates.json` och används sedan av bevakningen för resten av filerna i mappen. Redan parkerade filer granskas som förut, men allt nytt läses med mallen.
- **Originalfakturorna stannar i din egen mapp** — bevakade mappar kopierar inte längre originalen till `data/attachments/`: fakturan i registret pekar i stället på filen där den ligger i din originalmapp, och betal-PDF:en hämtar originalet via den sökvägen. Har en fil flyttats eller raderats sedan registreringen säger exporten nu ifrån (⚠ i resultatdialogen, statusraden och autoexport-loggen) i stället för att tyst hoppa över den. All fakturadata (belopp, OCR, förfallo, betald-status) ligger som förut i registret; fakturor som redan pekar på kopior i `data/attachments/` fungerar precis som tidigare.
- **Snabbvinster för kärnan** — tre förbättringar för att räkna ihop fakturor som ska betalas: **ATT BETALA står nu permanent i huvudfönstrets statusrad** (alla flikar) och i **tray-ikonens tooltip** så summan alltid är synlig utan att öppna appen; **snabbfilter-chips i Fakturor** (🔴 Förfallna · 📅 Idag & i morgon · 🗓 Inom 7 dagar) filtrerar på förfallodatum med ett klick — klicka igen för att stänga av; och **skanningen flaggar OCR med fel kontrollsiffra** (⚠ OCR-kontrollsiffra + orange text i statuskolumnen) redan i granskningslistan, innan registrering.
- **Fix: fönstret gick inte att få fram via tray-ikonen** — om en extern skärm kopplats bort (t.ex. docka/DisplayPort i vila) kunde fönstret ligga kvar på den försvunna skärmen: Qt ansåg det "synligt", så dubbelklick på tray-ikonen bara "aktiverade" ett osynligt fönster. Ny skärmvakt (`ensure_window_on_screen`) körs vid varje "Visa fönster"/tray-klick och vid start: ligger fönstret utanför alla anslutna skärmar centreras det på primärskärmen, och händelsen loggas (`WINDOW_OFFSCREEN_GUARD`).
- **Fokuspaket: bara räkna ihop fakturor som ska betalas** — åtta förbättringar som gör just det snabbare och säkrare: **OCR-kontrollsiffra (Luhn)** kontrolleras direkt i registreringsdialogen (varning medan du skriver + fråga vid spara), **dubblettvarning i realtid** så samma fakturanummer aldrig registreras två gånger för en leverantör, **beständig summarad** i Fakturor som alltid visar markeringens summa med tidigaste förfall (annars totalen att betala), **⚡ Betala idag**-knapp som markerar allt som förfaller idag/i morgon och öppnar sammanställningen, **💳 Kopiera betalinfo** i högerklicksmenyn (bankgiro + OCR + belopp färdigt för internetbanken), **Ångra med Ctrl+Z** (↩-knapp) för statusändringar som Markera betald, och **kredit-påminnelse på Dashboard** om kreditfakturor legat okvittade i över 30 dagar och riskerar att göra ATT BETALA för hög.
- **Betal-PDF:en omgjord för maximal tydlighet** — nya kolumner valda för betalning: Fakturanr, Leverantör, **OCR / referens** (det man knappar in i banken; Typ/Datum/Status borttagna), Förfallodatum och Belopp. Raderna sorteras alltid leverantör A–Ö → förfallodatum → fakturanummer, med **delsumma per leverantör** i listan. **Förfallna rader markeras röda** (fetstil + röd kantmarkering) mot betalningsdatumet. ATT BETALA står nu i 20 pt nästan-svart i en vit box med marinblå ram och guldstreck, betalningsdatumet i marinblå box med guldtext, och leverantörernas bankgiro i fetstil. Avdelarsidorna för original är vita med marinblått band och sidkontext ("2 / 5") i stället för helfärgade sidor. Hela dokumentet är dessutom **alltid ljust** — även om appen kör mörkt tema — så utskriften blir skarp och bläcksnål. Bonus: åäö skrivs nu korrekt i PDF:en (namn blev tidigare felstavade, t.ex. Betalningsdatum = tidigaste förfallet i batchen. Körs vid start och när fakturor ändras, tyst i bakgrunden när inget behövs, och varje körning hamnar i exporthistoriken.

### English
- **The watcher now says what it does + parked files are retried** — the log now shows at startup which watched folders were loaded (`SCAN_WATCH: bevakning startad …`), warns if a watched folder is missing (instead of silently skipping it every 30 seconds), and a file that was parked because the app didn't know the format back then is **automatically retried** once the app has learned the supplier or gained a built-in format via an update — parking is no longer a dead end where the file stays stuck even though the app can now read it. If the retry succeeds the invoice is registered as usual; otherwise it is parked again with the same reason.
- **Update straight from the tray menu** — right-clicking the Fakturabunten icon in the system tray now has **🔄 Check for updates …** (same flow as the Help menu): the window is brought to the front and the update dialog opens, so you don't have to open the app first just to update.
- **Verified supplier formats built in — no in-app teaching needed for them** — suppliers that were matched manually against real example invoices together with you (here in the chat) now have their format built into the app: **Martin G Anderson**, **Direktglas** (Saint-Gobain paper), **Pilkington**, **Swede Glass United** (invoice 19072: SEK 706.00) and **AAG Automotive** (invoice 1019: SEK 6,344.00). Built-in formats now also require the amount payable to sit on the same line as its label — in Swede Glass'/AAG's column summaries (header row followed by a value row) the first amount after the label would otherwise be the net/ex-VAT figure from the wrong column; such text is parked for review instead of being booked wrong. Watched folders register their invoices right away, without you first having to teach the app the supplier with 🎓, and the teach offer no longer appears for them when a folder is added. The format is recognised via the org. no./bankgiro or the printed name on the invoice itself (never via the registry entry's name, which may say Direktglas while the paper says Saint-Gobain) and always requires the invoice number + amount payable from the format itself — if the text arrives row-wise/column-broken or anything is missing, the file is parked for review exactly as before, never auto-registered with guessed values. Your own taught templates still take precedence, and for all other suppliers the same rule as before applies: teaching is required before the folder becomes automatic.
- **Originals now move exactly once — no Arkiv move at export** — a registered original gets its place in the year folder (`/pilkington/<invoice year>/`) when the invoice is registered, and there it stays. Previously it was moved a second time to `Arkiv/<export year>/` when exported as paid; that move is removed in both manual export and auto-export. Which invoices are paid is tracked by the registry (JSON) — the folder structure only mirrors the year. The scanning never enters Arkiv/, and originals already archived there keep working exactly as before.
- **Year sorting in watched folders** — registered invoices' originals are now automatically moved into a year folder by invoice date (`/pilkington/2023/…`) instead of piling up flat. New auto-registrations are sorted immediately, the existing pile is back-sorted on the next scan, and the registry path is updated either way. Parked (not-yet-registered) files are left untouched, and nothing moves without a readable date. Scanning now also sees files inside the year folders (so an invoice you dropped into `2023/` is processed), while the `Arkiv/` tree of paid originals is never rescanned. Export archiving to `Arkiv/<export year>/` works the same for year-sorted originals.
- **Invoice numbers are never read from the wrong column (found via real Martin G Anderson invoices)** — PDF text extracts either as label+value pairs or as a header row followed by a value row. Generic patterns and templates previously captured the next column header as the “invoice number” (e.g. “Fakturadatum”) or swallowed the rest of the line. Numbers are now read strictly as a single token, header words are never accepted as numbers, and templates skip pure header rows. Anything that cannot be read safely is left blank for you to pick/mark during teaching — the app never guesses a number from the wrong column. Verified against the layout: consolidated invoice 906178 (SEK 3,491.00 payable on page 2) and invoice 905034 read with the Fakturanr./Att betala/Fakturadatum/Förfallodatum labels; the per-order subtotals are not used as the invoice total.
- **Credit notes get the right amount + quantities no longer glue onto sums (found via real Saint-Gobain invoices)** — a credit note's total is labelled “Er Tillgodo”, but the parser didn't recognize the label and fell back to the first Summa line; at Saint-Gobain (“Summa Glas 1 2.642,50”) the **quantity 1 also glued onto the net amount**, yielding −12,642.50 instead of −3,303.00. “Tillgodo” is now a total label, and a lone integer in front of an amount reads as a quantity, not part of the sum. Verified against the layout: the two-page invoice 9750271120 (total on page 2) and credit note 9750269328 read completely after one teach — and the same template covers both invoices and credit notes, since the credit total falls back to the generic Tillgodo path when “Att Betala” is absent.
- **Two parsing format fixes (found via a real Pilkington/NSG invoice)** — amounts with **dots as thousand separators** (e.g. `4.374,00`) were previously read as 4.37; the last separator now decides what is decimal, so both Swedish `3.499,30` and US-style `1,234.56` parse correctly. **Year-first dates with dots or slashes** (`2026.10.15`, `2026/10/15`) are also recognized. Verified against the layout: after one manual match (template) the Pilkington invoice reads completely (invoice number, total 4,374.00, date, due date from “T.o.m.”); without a template it is safely parked for review as before — never registered with guessed values.
- **Invoices marked as paid now disappear from the export** — previously “Export all” also included invoices you had manually marked as paid (only Archived/Cancelled were excluded), so an already-paid invoice could be exported and paid twice by mistake. The export — and the export button's count — now use the same selection as everything else that counts unpaid: Paid/Archived/Cancelled are always excluded. Marking as paid works exactly as before: select the rows in Invoices and click **Mark as paid** (works for many at once, and can be undone with Ctrl+Z).
- **Credit-note detection when scanning + archive move of paid originals** — the parser now recognizes credit invoices/notes (the word on the document) and gives them a negative amount, so they **reduce** TO PAY instead of increasing it. And when an invoice from a watched folder has been exported (paid), its original is automatically moved to `<supplier folder>/Arkiv/<export year>/` — for both manual export and auto-export — while the register (JSON) is repointed to the new location so the original is still found for payment PDFs and history. The inbox stays clean and paid originals gather per year. Files outside watched folders are never touched, and a failed move never stops the export.
- **Max 10 invoices per export file + originals included by default** — every invoice is still its own row in the payment PDF, but one export file now holds at most 10 rows: more are automatically split into several files (`…-del1av3.pdf`, `…-del2av3.pdf`, …) with the same payment date and history + archiving per file. This applies both to manual export (all/selected) and to the per-supplier auto-export — 23 unpaid at one supplier become three files of 10/10/3, each with its own earliest due date as payment date. Also, **original invoices are now attached to the payment PDF by default** (can still be turned off in Settings → 📎 Include original invoices).
- **No auto-import until the supplier has been taught** — every supplier has its own layout/design, so a watched folder no longer registers automatically on generic guessing alone: the file is parked instead (reason “no template”) until you teach the app the supplier with the 🎓 button (a new offer shown right when the folder is added explains why). Once a template exists and actually matches the file, the folder becomes automatic again. Files parked before the teaching are also re-read with the template when you review them, and for **multi-page invoices** up to 30,000 characters of invoice text are now kept per file (up from 4,000) so the payment block on the last page isn't cut off when reviewing/re-teaching — extraction itself already read all pages.
- **Teach the app from a watched folder** — when you add a watched folder, the app now asks if you want to teach it to read that supplier's invoices (and the **🎓 Teach the app from the folder…** button is always in the watch panel): the app scans one of the PDFs in the folder and you manually mark which is the invoice number, amount, date, due date and OCR — the app shows right away what it finds for each field. The mapping is saved as a template in `data/invoice_templates.json` and is then used by the folder watcher for the rest of the files in the folder. Files already parked are reviewed as before, but everything new is read with the template.
- **Original invoices now stay in your own folder** — watched folders no longer copy originals to `data/attachments/`: the registered invoice instead points at the file where it lies in your original folder, and the payment PDF fetches the original via that path. If a file has been moved or deleted since registration, the export now says so (⚠ in the result dialog, the status line and the auto-export log) instead of silently skipping it. All invoice data (amounts, OCR, due dates, paid status) lives in the register as before; invoices that already point at copies in `data/attachments/` keep working exactly as before.
- **Quick wins for the core task** — three improvements for adding up invoices to be paid: **TO PAY is now permanently shown in the main window's status bar** (all tabs) and in the **tray icon tooltip**, so the total is visible without opening the app; **quick-filter chips in Invoices** (🔴 Overdue · 📅 Today & tomorrow · 🗓 Within 7 days) filter by due date in one click — click again to clear; and **scanning flags OCR numbers with a bad check digit** (⚠ OCR check digit + orange status text) right in the review list, before registration.
- **Fix: the window could not be brought up from the tray icon** — if an external monitor had been disconnected (e.g. a dock/DisplayPort display asleep), the window could remain on the vanished screen: Qt considered it "visible", so double-clicking the tray icon merely "activated" an invisible window. A new screen guard (`ensure_window_on_screen`) now runs on every "Show window"/tray click and at startup: if the window sits outside all connected screens it is centred on the primary screen, and the event is logged (`WINDOW_OFFSCREEN_GUARD`).
- **Focus pack: only add up the invoices that are to be paid** — eight improvements that make exactly that faster and safer: **OCR check digit (Luhn)** validated right in the registration dialog (warning while you type + confirm on save), **real-time duplicate warning** so the same invoice number is never registered twice for a supplier, a **persistent summary line** in Invoices always showing the selection total with earliest due date (otherwise the total to pay), a **⚡ Pay today** button that selects everything due today/tomorrow and opens the summary, **💳 Copy payment info** in the right-click menu (bankgiro + OCR + amount ready for the bank), **Undo with Ctrl+Z** (↩ button) for status changes such as Mark paid, and a **credit reminder on the Dashboard** when credit invoices have been unnetted for over 30 days and risk inflating TO PAY.
- **Payment PDF redesigned for maximum clarity** — new columns chosen for paying: Invoice no., Supplier, **OCR / reference** (what you type into the bank; Type/Date/Status removed), Due date and Amount. Rows are always sorted supplier A–Z → due date → invoice number, with a **subtotal per supplier** in the list. **Overdue rows are marked red** (bold + red edge stripe) against the payment date. TO PAY is now 20 pt near-black in a white box with a navy border and gold rule, the payment date sits in a navy box with gold text, and suppliers' bankgiro numbers are bold. Original divider pages are white with a navy band and page context ("2 / 5") instead of full-colour pages. The whole document is also **always light** — even when the app runs in dark theme — so printouts stay sharp and ink-friendly. Bonus: åäö now render correctly in the PDF (names were previously misspelled, e.g. "Langkvist").
- **Automatic batch export per supplier** (Settings → 🤖 Auto-export, off by default) — when a supplier reaches **10 unpaid invoices** they are automatically exported to a payment PDF with the originals attached and marked **Paid**; with fewer than 10 but the **nearest due date within 5 days** (or already overdue) they are exported right away and **printed together with the originals**, also marked Paid (otherwise they would re-export at every startup). Payment date = earliest due date in the batch. Runs at startup and whenever invoices change, silently in the background when nothing is due, and every run is recorded in the export history.
- **Readability & design pass** — larger, bolder typography throughout (14 px base, 15 px bold tabs, 14 px tables, Segoe UI 11 pt app font) and guaranteed contrast: near-black bold text on light themes and white bold text on dark (measured with the app's own WCAG module, at least 7:1 for body text). The Dashboard cards gained theme variants — white cards with navy text and a coloured top stripe in light mode — and an old rendering bug where cards were drawn as three separate strips (a selector-less style rule was inherited by the labels) is fixed with an ID selector + WA_StyledBackground.
- **Swish with a genuine QR code** — the donation dialog now shows a QR code in Swish's official original format (`C<number>;<amount>;<message>;<mask>`, number locked, amount and message editable) for the real number **072-181 71 77**, scannable directly in the Swish app. The number appears as a caption below the code and can still be copied. The `qrcode` library is installed automatically via ensure_packages; without it the copy button is shown as before.
- **Percentage in the update progress bar** — downloads now show % and MB (e.g. "62 % · 0.9 MB / 1.5 MB") right in the progress bar, and the install phase shows real percentage with a file counter ("Installing … file 24 of 48") instead of an endless spinner that looked like a freeze.
- **Combine selected invoices** — select e.g. 10 invoices in the Invoices tab and click 🧮 Combine selected: you get the total (credits deducted) and the due date of the earliest-due invoice, with the list sorted by due date, warnings for invoices without a date, a copyable summary — and export of exactly those invoices to a payment PDF with the earliest due date prefilled as the payment date. The status bar already shows the sum + earliest due while selecting.
- **Updater improved** — the app now checks for a new version silently in the background at startup (at most once a day, can be turned off in the Settings menu) and only asks when a newer build actually exists — an old copy can no longer keep running unnoticed. The dialog gained restore-from-latest-backup (↩ in bak/) in case an update misbehaves, and the progress bar now also shows the install phase. Auto-checks open the dialog pre-filled (no double network round-trip).
- **In-app updates** — Help → 🔄 Check for updates … fetches the latest release from GitHub, shows the notes and can download + install it in one click. Only program files are replaced: data/, js/, ui/data/, settings.json, logs and exports are never touched, and a backup is saved to bak/ before anything is replaced. Comparison is per commit, so an updated v1.0.0 release is found even with the same version number.
- **Watched folders + originals in the payment PDF** — add one watched folder per supplier in the Import tab (e.g. Pilkington, Direktglas): new invoice files are parsed and registered automatically, incomplete ones are parked for review, and the same file is never imported twice (content hash + duplicate check against the register). Originals are copied to `data/attachments/<supplier>/` and can be appended after the payment PDF (Settings → 📎 Include original invoices) with a divider page per invoice.
- **A real Dashboard** — the start page is no longer a placeholder: four stat cards (TO PAY, OVERDUE, DUE IN 7 DAYS, SUPPLIERS) in navy/gold plus a "Due soon" list with double-click straight to Invoices. Same status rules and amount format as the Invoices tab.
